# Соглашение о коммитах — Exerciser

Проект использует [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/).

---

## Формат

```
<тип>[(<область>)]: <описание>

[тело]

[подвал]
```

- **Заголовок** обязателен и умещается в 72 символа.
- **Тело** и **подвал** опциональны, отделяются пустой строкой.

---

## Типы коммитов

| Тип        | Назначение                                  |
|------------|---------------------------------------------|
| `feat`     | Новая функциональность                      |
| `fix`      | Исправление бага                            |
| `refactor` | Рефакторинг (без изменения поведения)       |
| `test`     | Добавление или правка тестов                |
| `docs`     | Документация                                |
| `chore`    | Рутинные задачи (зависимости, настройки)    |
| `style`    | Форматирование, кодстайл (без логики)       |
| `perf`     | Оптимизация производительности              |
| `ci`       | CI/CD                                       |
| `build`    | Сборочная система, Docker                   |

---

## Область (scope) — опционально

Уточняет, какая часть проекта затронута:

`security`, `api`, `frontend`, `admin`, `docker`, `validation`, `config`, `tests`, `db`, `student`, `docs`

Пример: `feat(security): перенести проверку ответов на сервер`

---

## Описание

- На **русском** языке.
- В **повелительном** наклонении: «добавить», «исправить», «удалить».
- Со **строчной** буквы.
- **Без точки** в конце.
- Не длиннее **72 символов**.

---

## Примеры

```
feat(security): перенести проверку ответов на сервер
fix(api): убрать утечку правильных ответов в QuestionSnapshotDto
refactor(backend): вынести общую логику в extension-методы
test: добавить unit-тесты для AttemptsController
docs: актуализировать описание API в README
ci: исправить имя solution-файла в GitHub Actions
chore(deps): обновить Microsoft.EntityFrameworkCore до 9.0
```

---

## Breaking changes

- `!` после типа: `feat(api)!: изменить формат ответа попытки`
- Или `BREAKING CHANGE:` в подвале.

## Именование веток

| Ветка        | Назначение                        |
|--------------|-----------------------------------|
| `feature/*`  | Новый функционал                  |
| `fix/*`      | Исправление багов                 |
| `hotfix/*`   | Срочные правки в продакшен        |
| `release/*`  | Подготовка релиза                 |
| `chore/*`    | Рутина (CI, зависимости, конфиги) |
